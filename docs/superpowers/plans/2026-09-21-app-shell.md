# JT App Shell implementation plan

Goal: implement the user's approved P0–P2 performance design on feat/singularity-workbench, preserving all paid request contracts and recovery behavior.

Architecture: one top-level shell owns history, navigation and the existing black-hole renderer. Each page mounts once in a ShadowRoot, with a scoped document adapter and explicit element references generated by an AST pass. Existing builders remain authoritative; a new final build step emits page modules, markup fragments, styles and content-addressed resources. No iframe, eval or whole-document navigation is required for page switching.

Constraints: no production deployment, no paid tests, no merges; retain release gates. Existing generated legacy pages remain regression fixtures and rollback inputs. Server changes are restricted to static routing/cache headers. Keys and server configuration never enter browser manifests.
